## Change from .3

Seeking an open-GOP H.264 file onto a keyframe that is a recovery point rather
than an IDR (common in YouTube downloads) could fail in .3 with
`DUSKCUT_MF_DYNAMIC_FORMAT_UNSUPPORTED` or return no pictures; transport-stream
seeks could lose their first picture. `h264_mp4toannexb` gains the opt-in
`resume_ps` option (set only by `h264_mf`) and the Windows bridge tracks the
real stream format, waits for a decodable start and honours recovery counts.
Stream copy and remux behaviour is unchanged.

## Functional evidence and limits

Native comparisons ran on one Windows 11 account against the build artifact,
whose executables are byte-identical to the ZIP. Reference decoders are QA
tools only, never shipped or used as a fallback.

- `test-recovery-seek.mjs`: 124/124 rows passed. With .3 as the previous
  build, 47 of its 48 defect rows failed (the remaining one lands on an IDR)
  and all 20 control rows passed on both builds.
- Real downloaded videos (local copies, not redistributed): a 1080p MP4 whose
  keyframes are mostly recovery points gave 113/113 bit-exact seeks
  (first eight pictures, timestamps and checksums) on .4 versus 53/113 on .3,
  where the other 60 reported the false format-change marker. A vertical short
  gave 79/79 on .4 versus 22/79 on .3. An all-IDR 1080p download, used as a
  control, gave 113/113 on both builds.
- No regression on ordinary files: sample-accurate cut timing 33/33 and
  rotation cut timing 44/44 on both builds with identical results; the
  H.264/HEVC/AAC runtime suite 19/19 with decoded output byte-identical to .3
  on every row; colour/VUI decode 6/6 pixel-exact; H.264 encode metadata 4/4;
  dynamic-format rejection 3/3. Four colour rows that request HEVC encoding
  fail on both builds because HEVC encoding is disabled by design; they are not
  counted as passing.

This account now has a Windows HEVC decoder, so HEVC decode rows ran and
passed here; that is one account, not an HEVC profile or driver matrix. Editor
application tests and a signed installer are separate steps and are not
established by this component review.

Before publishing an editor installer, inspect its actual bundled executable
hashes (allowing only an independently verified Authenticode addition), source
links, licences and application smoke tests. Source availability is not proof
of the contents of a not-yet-built installer.
